## Usage

With a [Basecoat style bundle](/installation) loaded, add `.bubble` to a `<div>`. Its first child is the content; an optional second `<div>` holds reactions. The root class does not require a particular HTML element. Use `.bubble-group` for closely spaced bubbles. No Bubble JavaScript is required.

```html
<div class="bubble">
  <p>I checked the registry output and removed the stale route.</p>
  <div role="img" aria-label="Reaction: thumbs up">
    <span>👍</span>
  </div>
</div>
```

Bubbles size to their content, up to 80% of their container. Put them in a column flex layout so `data-align="end"` can align outgoing messages. Leave room between messages for overlapping reactions.

The conversation examples use an ordered list with one `<li>` per message. Sender labels use `sr-only` to preserve upstream's appearance while identifying who spoke. Keep the list's `role="list"` so Safari exposes its semantics when Tailwind removes list markers. The static previews do not announce updates.

These examples use upstream's blue theme through local CSS variables. Omit those variables to use your application's theme. Avatars, sender names, timestamps, and message-level controls belong outside the bubble.

### HTML structure

<dl>
  <dt><code>&lt;div class="bubble"&gt;</code></dt>
  <dd>
    Message bubble. Use <code>data-align="end"</code> for an outgoing bubble.
    <dl>
      <dt><code>&lt;p&gt;</code> or another element</dt>
      <dd>The first child holds the message content.</dd>
      <dt><code>&lt;div&gt;</code> <span class="badge" data-variant="secondary">Optional</span></dt>

  <dt><code>&lt;div class="bubble-group"&gt;</code> <span class="badge" data-variant="secondary">Optional</span></dt>
  <dd>Groups closely spaced bubbles from the same sender.</dd>
</dl>

  <li class="flex min-w-0 flex-col gap-2">
    <p class="self-end text-xs text-muted-foreground">Bob · <time datetime="2026-11-07T18:19:00+08:00">18:19</time></p>
    <div class="bubble" data-align="end">
      <p>Yes, the changes look good.</p>
    </div>
  </li>
</ol>
</Preview>

For a live conversation, put the list inside a named `role="log"` wrapper. This [chat-log pattern](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA23) announces new messages politely without moving focus. Keep the list role on the `<ol>`; do not replace it with `log`.

```html
<div role="log" aria-label="Conversation">
  <ol role="list">
    <li>
      <p>Alice · <time datetime="2026-11-07T18:18:00+08:00">18:18</time></p>
      <div class="bubble">
        <p>Here is the updated document.</p>
      </div>
    </li>
  </ol>
</div>
```

Create the live-region wrapper before appending new messages. For streamed replies, batch announcements rather than announcing each token. A static transcript only needs the list, as in the preview above.
