# Toast

A short notification for an action, status update, or asynchronous task.

<Preview>
<button type="button" class="btn" data-variant="outline" onclick="document.getElementById('toaster').toast({ category: null, title: 'Event created', description: 'Sunday, December 3 at 9:00 AM', action: { label: 'Undo' } })">Show Toast</button>
<ol id="toaster" class="toaster" role="list" aria-label="Notifications"></ol>
</Preview>

## Usage

<Callout title="Template macros available" icon="code" action={{ label: "More", href: "/templates#toast" }}>
  This component ships `toaster()` and `toast()` macros for Jinja and Nunjucks.
</Callout>

<Steps>
  <Step title="Include CSS">

Import Tailwind and one Basecoat style bundle.

```css
@import 'tailwindcss';
@import 'basecoat-css/vega.css';
```

Or import the base CSS, Toast and Button component CSS, and one style pack.

```css
@import 'tailwindcss';
@import 'basecoat-css/base.css';
@import 'basecoat-css/components/button.css';
@import 'basecoat-css/components/toast.css';
@import 'basecoat-css/styles/vega.css';
```

  </Step>
  <Step title="Include JavaScript">

Copy or serve the full bundle, or the Basecoat runtime and Toast script:

```html
<script src="/assets/js/basecoat.min.js" defer></script>
<script src="/assets/js/toast.min.js" defer></script>
```

For CDN and bundler imports, see [Installation](/installation).

  </Step>
  <Step title="Add the toaster">

Add one container near the end of the page body. Toasts can be created from JavaScript or appended as server-rendered HTML.

```html
<ol id="toaster" class="toaster" role="list" aria-label="Notifications"></ol>
```

  </Step>
  <Step title="Show a toast">

Call the toaster after the Basecoat scripts initialize, for example when the user completes an action.

```js
const toaster = document.getElementById('toaster');
toaster.toast({
  category: null,
  title: 'Event created',
  description: 'Sunday, December 3 at 9:00 AM',
});
```

Toasts include a close button by default. Footer buttons and links dismiss their toast after their own click handler runs; no extra action attributes are needed.

The three newest toasts form a stack. Hover or focus it to expand them and pause dismissal. Swipe a toast down or toward its horizontal edge to dismiss it. Closing a focused toast moves focus to another toast control or back to the previously focused element. Motion follows the user's reduced-motion preference.

  </Step>
</Steps>

### HTML structure

Use a `.toast` list item, a `.toast-content` wrapper for the message and its fade transition, a `<section>` for text, and an optional `<footer>` of ordinary [Button](/components/button) controls. An optional decorative SVG goes before the section. Existing non-list roots still initialize through the same classes; use list items for valid markup inside an `<ol>`.

```html
<li class="toast">
  <div class="toast-content" role="status" aria-atomic="true">
    <section>
      <h2>Event created</h2>
      <p>Sunday, December 3 at 9:00 AM</p>
    </section>
    <footer>
      <button type="button" class="btn" data-variant="outline" data-size="sm">Undo</button>
      <button type="button" class="btn" data-variant="ghost" data-size="icon-sm" aria-label="Close toast">
        <svg aria-hidden="true" xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M18 6 6 18"/><path d="m6 6 12 12"/></svg>
      </button>
    </footer>
  </div>
</li>
```

Set `data-category="success|info|warning|error|loading"` on the toast when applicable. Use `role="alert"` for error content and `role="status"` for other notifications. Set `data-duration` in milliseconds, or `-1` to keep it open. A loading toast stays open until updated or dismissed.

### JavaScript API

| API | Description |
| --- | --- |
| `toaster.toast(config)` | Creates and returns a toast element. |
| `toaster.closeAll()` | Closes every toast in the container. |
| `toast.close()` | Closes one initialized toast. |
| `toast.update(config)` | Updates a toast created by `toaster.toast()`, retaining unspecified options and restarting its timer. Does nothing after dismissal. |

#### Config object

| Option | Description |
| --- | --- |
| `title` | Notification title. Optional for description-only toasts. |
| `description` | Optional description. |
| `category` | `success`, `info`, `warning`, `error`, or `loading`. Defaults to `info`; use `null` for no status icon. |
| `duration` | Milliseconds before dismissal. Defaults to `3000`, or `5000` for errors. Loading toasts default to no timeout. Use `-1` to keep a toast open. |
| `action` | Optional `{ label, href }` link or `{ label, onclick }` button. A label-only button simply dismisses the toast. |
| `cancel` | Optional secondary `{ label, onclick }` button. |
| `closeButton` | Whether to include the close icon button. Defaults to `true`. |
| `icon` | Optional trusted SVG markup replacing the category icon. |
| `html` | Allow HTML in the title, description, and labels. Defaults to `false`. |

Basecoat keeps its existing `category`, `duration`, and DOM-element API. Its default category and timeout differ from upstream. The Promise example below uses native promises with `toast.update()` instead of a separate promise manager.

<Callout type="warning" title="Text is escaped by default" icon="triangle-alert">
  `title`, `description`, and labels are plain text unless `html: true`. Only use that option with trusted content. `icon` is raw markup and `onclick` is JavaScript code; neither should contain user input.
</Callout>

The Jinja and Nunjucks macros use your template engine's autoescaping. For Jinja, enable autoescaping for `.html.jinja` files. Their optional `close_button` argument defaults to `true`; existing positional arguments are unchanged.

## Examples

### Types

Use `category` to choose a status icon. The Default example sets `category: null` to omit the icon.

<Preview>
<div class="flex flex-wrap gap-2">
  <button type="button" class="btn" data-variant="outline" onclick="document.getElementById('toaster').toast({ category: null, description: 'Event has been created.' })">Default</button>
  <button type="button" class="btn" data-variant="outline" onclick="document.getElementById('toaster').toast({ category: 'success', description: 'Event has been created.' })">Success</button>
  <button type="button" class="btn" data-variant="outline" onclick="document.getElementById('toaster').toast({ category: 'info', description: 'Arrive 10 minutes before the event.' })">Info</button>
  <button type="button" class="btn" data-variant="outline" onclick="document.getElementById('toaster').toast({ category: 'warning', description: 'The event cannot start before 8:00 AM.' })">Warning</button>
  <button type="button" class="btn" data-variant="outline" onclick="document.getElementById('toaster').toast({ category: 'error', description: 'The event could not be created.' })">Error</button>
</div>
</Preview>

### Action

Add an action to the footer. Its handler runs before the toast closes.

<Preview>
<button type="button" class="btn" data-variant="outline" onclick="document.getElementById('toaster').toast({ category: null, title: 'Event created', action: { label: 'Undo', onclick: 'console.log(\'Undo event creation\')' } })">Show Action</button>
</Preview>

```js
toaster.toast({
  category: null,
  title: 'Event created',
  action: {
    label: 'Undo',
    onclick: 'undoEvent()',
  },
});
```

### Promise

Update the same toast as a native promise settles. The loading state has no timeout; changing to success or error starts that category's default timeout. Dismissing the toast while the task runs does not cancel the task or recreate the notification later.

<Preview>
<button
  type="button"
  class="btn"
  data-variant="outline"
  onclick="const toast = document.getElementById('toaster').toast({ category: 'loading', description: 'Creating event…' });
    new Promise(resolve => setTimeout(() => resolve({ name: 'Event' }), 2000)).then(
      data => toast.update({ category: 'success', description: data.name + ' created.' }),
      () => toast.update({ category: 'error', description: 'Could not create event.' })
    )"
>Create Event</button>
</Preview>

```js
const toast = toaster.toast({
  category: 'loading',
  description: 'Creating event…',
});

createEvent().then(
  (data) => toast.update({ category: 'success', description: `${data.name} created.` }),
  () => toast.update({ category: 'error', description: 'Could not create event.' }),
);
```

### From the server

Append HTML from your backend. Basecoat initializes new toasts automatically; the same markup works without a JavaScript configuration object.

<Preview>
<button type="button" class="btn" data-variant="outline" hx-trigger="click" hx-select="unset" hx-get="/fragments/toast/success" hx-target="#toaster" hx-swap="beforeend" hx-push-url="false">Toast from backend (with HTMX)</button>
</Preview>

### Placement

Set `data-align="start"`, `center`, or `end` on the toaster. The default is `end`; start and end follow the page's text direction.

```html
<ol id="toaster" class="toaster" data-align="start" role="list" aria-label="Notifications"></ol>
```

### Custom dismissal

Keep a toast open and use a text button instead of the default close icon.

<Preview>
<button type="button" class="btn" data-variant="outline" onclick="document.getElementById('toaster').toast({ category: null, title: 'Changes saved', description: 'You can close this notification when you are ready.', duration: -1, closeButton: false, cancel: { label: 'Dismiss' } })">Persistent Toast</button>
</Preview>
