## Usage

<Steps>
  <Step title="Load the styles and scripts">

Load a Basecoat style bundle and the Basecoat runtime with `carousel.js`, or use the full JavaScript bundle. See [Installation](/installation).

```html
<script src="/assets/js/basecoat.min.js" defer></script>
<script src="/assets/js/carousel.min.js" defer></script>
```

  </Step>
  <Step title="Add slides and controls">

Use a `.carousel` root, a direct child `<ul>`, and `<li>` slides. Add `scrollbar` to the list for a themed scrollbar and `tabindex="0"` so keyboard users can scroll it. Native scrolling, touch gestures, and snapping work without JavaScript. Style packs give slides padding to leave room for card shadows; use padding utilities on the `<li>` to customize it.

```html
<div class="carousel" role="region" aria-roledescription="carousel" aria-label="Featured items">
  <ul role="list" class="scrollbar" tabindex="0" aria-label="Slides">
    <li>First slide</li>
    <li>Second slide</li>
    <li>Third slide</li>
  </ul>
  <button type="button" class="btn" data-variant="outline" hidden>Previous</button>
  <button type="button" class="btn" data-variant="outline" hidden>Next</button>
</div>
```

The two optional buttons are direct children: Previous first, then Next. Keep them `hidden` until the script initializes. The script scrolls to the next slide’s start and disables buttons at the ends. It also updates when slides are added, removed, or resized. Position the buttons with utilities, as in the preview.

  </Step>
</Steps>

Unlike upstream’s Embla carousel, this uses browser scrolling. It does not provide looping, autoplay, mouse-drag handling, or Embla’s plugin/API system. Touch and trackpad scrolling remain native. Smooth scrolling respects reduced-motion preferences.

Arrow keys work when the list or a previous/next button has focus, respecting orientation and RTL. Keys inside slide content are left alone. When a focused control becomes disabled at an end, focus moves to the other control (or the list if neither can scroll).

Slides intentionally keep native list semantics instead of upstream’s ARIA slide groups. `role="list"` preserves those semantics in browsers that otherwise omit unstyled lists from the accessibility tree. Real buttons share Basecoat Button styles across themes; their shape follows the style pack: fully round in Vega, Nova, Maia, Mira, and Luma; `rounded-2xl` in Rhea; and the ordinary Button shape in Lyra and Sera. The script enhances native scrolling rather than using CSS-generated scroll buttons and maintaining a second fallback control system.

### HTML structure

<dl>
  <dt><code>&lt;div class="carousel" role="region" aria-roledescription="carousel" aria-label="&#123; LABEL &#125;"&gt;</code></dt>
  <dd>
    Carousel root. Use <code>data-orientation="vertical"</code> for a vertical carousel.
    <dl>
      <dt><code>&lt;ul tabindex="0" aria-label="Slides"&gt;</code></dt>
      <dd>
        Direct-child scrollable list. Add <code>role="list"</code> to preserve list semantics where needed.
        <dl>
          <dt><code>&lt;li&gt;</code></dt>
          <dd>One slide containing its content.</dd>
        </dl>
      </dd>
      <dt><code>&lt;button type="button" hidden&gt;</code> <span class="badge" data-variant="secondary">Optional</span></dt>
      <dd>Two direct-child controls: Previous followed by Next. The script reveals and updates them.</dd>
    </dl>
  </dd>
</dl>

### Orientation

Set `data-orientation="vertical"` and give the list a fixed height. Center the buttons with `inset-x-0 mx-auto` in either text direction. Subtract the gap from the available height before dividing it between two slides: `basis-[calc((100%_-_0.25rem)/2)]` with `gap-1`. This keeps both cards fully visible, including at the end.

### Without buttons

Omit the buttons and JavaScript when native scrolling is sufficient. Add `scrollbar` to the `<ul>` to reuse [Scroll Area](/components/scroll-area)'s themed scrollbar. Keep the list keyboard-focusable; touch and trackpad gestures also scroll it. Carousel hides the scrollbar once its previous/next controls initialize. This native scrolling fallback is an intentional addition to upstream's button-driven carousel.
